# MCHOSE V9 Turbo+ 电量适配与验证

关联问题：[#1](https://github.com/echoinzephyr/PeriRing/issues/1)。

## 范围与当前状态

本适配器独立于迈从鼠标协议，仅处理 `VID 3837 / PID 600A`、路径包含 `&mi_00` 的厂商 HID 集合（UsagePage >= `FF00`）。`6008` 灯控、`6009` 有线、`600D` Turbo 和其他型号均不在本次适配范围。

当前为待硬件验证的实现。开发环境缺少 .NET 10 SDK 与 WinUI 完整构建条件，没有完成应用编译、官方驱动对照或实际耳机读写验证。新增回归用例使用合成报文，不能替代实机结果。

## 协议依据

- [OpenMHub headset.js（固定提交）](https://github.com/brayanspagnol/OpenMHub/blob/f77c000334ad9e34499d7acab315a0d9ee8789b7/app/renderer/drivers/headset.js)
- [OpenMHub 的合成设备测试](https://github.com/brayanspagnol/OpenMHub/blob/f77c000334ad9e34499d7acab315a0d9ee8789b7/tools/check-headset.mjs)

参考项目也声明耳机实现尚未经过真实硬件验证。这里使用其明确的型号、只读查询格式与状态定义，并保留 MIT 声明；没有移植设置、灯效或固件操作。

Windows 输入与输出报告均限制为 64 字节。格式不符时返回无电量的设备说明，不打开设备、不试发查询；请根据实测描述符决定是否扩展。

| 字段 | 格式 |
|---|---|
| 输出报告 ID | `55` |
| 查询内容 | `65 01`，由现有传输层补零至完整输出报告长度 |
| 回复前缀 | `55 65 <电量> <状态>` |
| 电量 | `0..100`，保持原始百分比，不套用迈从鼠标分档 |
| 状态 `02` | 放电，有效实时读数 |
| 状态 `03` | 充电，有效实时读数 |
| 状态 `04` | 已充满，保留设备上报值，不补造 100% |
| 状态 `1A` | 休眠或离线，不作为实时读数 |
| 其他状态 / 报告 | 忽略，不将空白、无效或无关回复显示为 0% |

使用现有 `HidConnection` 的同一中断流完成读写。每轮最多查询 3 次，每次最多读取 6 个回复，每次读取限时 150 ms；取消沿用扫描 token。失败后继续使用项目已有的无读数与历史缓存处理。

## 交给维护者的验证步骤

1. 在配置好 .NET 10 SDK 和 Windows App SDK 构建组件的环境运行 `build.ps1`，确认 WinUI 资源正常发布。
2. 运行生成的 `BatteryDisplay.exe --self-test`，确认新增的 `MchoseHeadsetTests` 随原有协议测试执行。
3. 连接 V9 Turbo+ 的 2.4G 接收器，运行 `BatteryDisplay.exe --debug --export-diagnostics`。检查诊断包中的匹配适配器、`MI_00` 对应的 UsagePage / Usage、输入输出长度及查询结果。
4. 若接口格式不符，先查看描述符和官方查询流量，核对报告 ID `55` 与长度，再调整匹配范围或报告格式；不要仅按品牌放宽条件。
5. 对比官方驱动同一时刻的电量、充电状态。分别测试官方驱动运行和退出两种情况，记录是否有接口占用。
6. 检查耳机关机、休眠、唤醒、充电、充满与接收器拔出的状态；旧读数只能使用现有的“上次电量”标记。
7. 同时连接已支持的鼠标，确认两台设备单独显示，耳机读取失败不会移除鼠标读数。

维护者根据编译和实测结果决定继续修改、合并及回复 Issue。PR 中使用 `Refs #1` 关联问题，不自动关闭问题。
